OpenRath image generation list
==============================

Purpose
-------
Plan new documentation images for the current OpenRath update. This file is
for an async LLM/agent that will read the referenced source and produce images
for `docs/source/_static/`.

Style rules
-----------
- Prefer clean OSS documentation diagrams over marketing art.
- Use simple horizontal layouts (`flowchart LR` style) where possible.
- Keep node labels short and consistent.
- Use the existing docs image vocabulary as reference:
  `docs/source/_static/core-provider.png`,
  `core-session.png`, `core-backend.png`, `core-tool.png`, `core-workflow.png`.
- Output PNG files suitable for Sphinx figures, ideally 1600x900 or 1800x1000.
- Use transparent or white/light background unless matching the existing docs
  theme requires otherwise.
- Avoid decorative gradients, mascots, or large illustration-only scenes.
- Each diagram should teach one concept.

```mermaid
  T --> File
  File --> Load["load_session"]
  Load --> Pair["resumable pair"]
```

Visual notes:
- Show JSONL as a file with ordered rows.
- Mark `trailer` as "closed=True"; missing trailer as "closed=False".
- Use a small warning callout for crash detection.

Acceptance criteria:
- A reader can distinguish session persistence from sandbox persistence.
- The diagram makes clear that resume does not open a sandbox immediately.

- `tests/session/test_session_fork_detach_merge.py`

Key facts to represent:
- `Backend.open()` returns a sandbox with `refcount == 0`.
- `Session.require_sandbox()` or `bind_sandbox()` acquires one reference.
- `run_session_loop`, `run_session_compress`, `fork`, `detach`, `merge`
  share a live handle and increment refcount.
- `close_sandbox()` releases one reference.
- Backend closes when refcount reaches zero.

Suggested layout:

```mermaid
flowchart LR
  Open["Backend.open"] --> S["BackendSandbox ref=0"]
  S --> A["user Session ref=1"]
  A --> F["fork/detach ref=2"]
  A --> L["loop output ref=3"]
  F --> Close1["close one"]
  L --> Close2["close all"]
  Close2 --> Done["backend.close"]
```

Visual notes:
- Use small counters on sandbox node: ref=0, ref=1, ref=2.
- Show close only on final release.

Acceptance criteria:
- A reader understands why sandbox reuse improved.
- A reader understands how to get independent branches: retarget with `.to(...)`.

```mermaid
  D2 --> CB
  D3 --> CB
  D1 --> Acc["accumulate"]
  D2 --> Acc
  D3 --> Acc
  Acc --> Chunk["assistant chunk"]
```

Visual notes:
- Show two paths from deltas: UI callback and durable session chunk.
- Add "OpenAI yes / Anthropic no" as a small compatibility badge.

Acceptance criteria:
- The image prevents the misconception that every stream token becomes a session row.

Implementation workflow for async image agent
---------------------------------------------

For each selected image:

1. Read the listed source files and docs.
2. Draft a Mermaid diagram first.
3. Check labels for correctness against source symbols.
4. Render to PNG in `docs/source/_static/<filename>`.
5. Keep source diagram text in a sidecar file if useful:
   `docs/source/_static/<filename>.mmd`.
6. Add a Sphinx figure to the target docs page.
7. Run:
   `mamba run -n rath-dev python -m sphinx -W -b html docs/source docs/_build/html`
8. Visually inspect the generated HTML page.
